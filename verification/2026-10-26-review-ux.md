# Review workflow usability verification — 26 October 2026

Implemented a three-stage review workspace: Choose clips → Edit → Review & export.
Existing bridge/render contracts and media manifests are unchanged.

## Behavior checked

- Concise candidate cards show title, description, duration, aspect ratio, current
  state, and expandable rationale. An explicit Open clip selects a saved candidate.
- Desktop shows the video beside the transcript. Source footage and rendered
  Edited preview have separate, clearly labeled modes. Layout guides are opt-in
  under Advanced and do not masquerade as a rendered composite.
- Keep/remove and target-duration controls propose changes before a separate Save
  changes request. Detailed commands, cleanup, protection and restore stay available
  in More editing tools. Production controls/history remain in Advanced.
- Unsaved plan/caption changes block clip switching and final/batch approval. A
  current saved preview remains mandatory for final approval. Preview and final
  rendering are explicit separate actions. Readiness failures have Retry checks.
- Caption corrections are independently saved. Busy navigation is disabled.
- Final clips open at Review & export; batch rendering is a collapsed secondary
  task, and packaging becomes available after at least one final exists.
- Standalone plan import still opens the source/plan review and retains its legacy
  direct-render approval, without pretending it is a staged saved review session.
- Fixed SSR hydration mismatch on the new loading view and avoided fetching the
  sample project's nonexistent captions on an empty workspace.

## Limits

- This is the local review workspace, not the upstream native timeline editor.
- Export folder paths can be relative to the launcher's media root; the UI labels
  these explicitly. There is no one-click Finder launch or final-video download.
- Existing final clips remain immutable. This pass adds no automatic regeneration,
  ranking, reframing, dubbing, generative media, or external provider validation.
- Browser-render verification used generated media. The podcast's prior render
  artifacts were inspected through the existing UI without requesting new renders.
